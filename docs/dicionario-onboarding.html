Visão Geral Do Desafio

O desafio pede uma aplicação em Node.js, TypeScript e AdonisJS para sincronizar preço e estoque de produtos da Plugar.me com a Amazon Brasil. A Amazon usada no teste não é real: existe uma API mock que simula as respostas esperadas.

Ideia principal: buscar produtos na origem, filtrar os produtos válidos, transformar os dados no formato que a Amazon espera e enviar uma atualização parcial da oferta.

O desafio não pede criação de anúncios, importação de pedidos, painel administrativo, banco de dados, autenticação de usuários nem integração com a Amazon real. O foco está em integração, tratamento de token, qualidade de código e robustez diante de falhas.

O que precisa acontecer

  • Consultar produtos, preços e estoques na API mock da Plugar.me.
  • Consultar credenciais Amazon do cliente na API mock da Plugar.me.
  • Renovar o token Amazon usando o refresh token.
  • Atualizar preço e estoque dos SKUs válidos na API mock da Amazon.
  • Gerar um resultado com itens publicados, ignorados e falhas.

Mapa Do Fluxo

O fluxo abaixo mostra a ordem mental mais simples para entender a solução. Uma implementação real pode dividir isso em classes e métodos, mas a lógica central permanece a mesma.

1
Disparo da sincronização Uma rota HTTP ou comando Ace inicia o processo. Exemplo: POST /sync/amazon/offers.
2
Busca de dados Plugar.me A aplicação consulta produtos, preços, estoques e credenciais Amazon do cliente.
3
Renovação do token O access token inicial está expirado. A aplicação usa o refresh token para obter um token válido.
4
Filtro e mapeamento dos produtos Cada produto é validado: ativo, com preço válido e com estoque da filial configurada.
5
PATCH na Amazon Listings mock A aplicação envia preço e quantidade no payload esperado pela Amazon.
6
Resultado final O retorno informa quantos SKUs foram publicados, ignorados ou falharam.

Linguagens, Frameworks E Ferramentas

Node.js runtime

Node.js é um ambiente de execução para JavaScript fora do navegador. Ele permite criar servidores, scripts, APIs, integrações, ferramentas de linha de comando e aplicações backend.

Ele não é uma linguagem. A linguagem é JavaScript. O Node.js é o programa que executa JavaScript no backend e fornece acesso a recursos como arquivos, rede, HTTP, variáveis de ambiente e processos.

TypeScript linguagem

TypeScript é uma linguagem baseada em JavaScript que adiciona tipos. No fim, o TypeScript é convertido para JavaScript para ser executado pelo Node.js.

No desafio, TypeScript ajuda a descrever contratos: o formato de um produto Plugar.me, de uma credencial Amazon, de um payload de atualização e do resultado final da sincronização.

AdonisJS framework backend

AdonisJS é um framework backend para Node.js. Framework é um conjunto de ferramentas, padrões e estruturas que ajuda a construir uma aplicação de forma organizada.

Ele não é linguagem, não é banco de dados e não é servidor externo. Ele é uma base de aplicação que fornece rotas, controllers, comandos Ace, validação, logger, configuração, injeção de dependências e organização de código.

Por que AdonisJS é framework? Porque ele define uma estrutura de desenvolvimento e entrega peças prontas para resolver problemas comuns de backend. Você escreve a regra de negócio dentro dessa estrutura em vez de montar tudo manualmente do zero.

Ace CLI do AdonisJS

Ace é a ferramenta de linha de comando do AdonisJS. Ela permite executar comandos do projeto, como criar arquivos, rodar tarefas e disparar rotinas internas.

No desafio, a sincronização pode ser disparada por uma rota HTTP ou por um comando Ace. Um comando Ace seria útil para algo como node ace sync:amazon-offers.

npm gerenciador de pacotes

npm é usado para instalar bibliotecas, rodar scripts e gerenciar dependências de projetos Node.js. O arquivo package.json declara os scripts e pacotes usados pelo projeto.

API, REST E HTTP

API contrato entre sistemas

API significa Application Programming Interface. Em termos práticos, é uma forma definida de um sistema conversar com outro. Uma API diz quais operações existem, quais dados enviar, quais respostas esperar e quais erros podem acontecer.

Nem toda API é web. Existem APIs de bibliotecas, APIs de sistema operacional, APIs internas de código e APIs HTTP. Neste desafio, quando falamos API, estamos falando principalmente de API HTTP.

API REST estilo arquitetural

REST é um estilo de arquitetura para construir APIs usando conceitos da web, principalmente HTTP, recursos e métodos como GET, POST, PATCH e DELETE.

Uma API REST costuma organizar URLs em torno de recursos. Exemplo: /produtos representa uma coleção de produtos. Uma chamada GET /produtos busca produtos; uma chamada PATCH /produtos/123 altera parcialmente o produto 123.

Diferença simples: API é o contrato de comunicação. REST é um estilo específico para desenhar APIs, normalmente usando HTTP e recursos bem definidos.

HTTP protocolo

HTTP é o protocolo de comunicação usado na web. Ele define como um cliente envia uma requisição e como um servidor devolve uma resposta.

No desafio, a aplicação AdonisJS será cliente das APIs mock. Ela enviará requisições HTTP para buscar dados e atualizar ofertas.

Método HTTP Significado Uso no desafio
GET Buscar informações sem alterar o recurso. Buscar produtos e credenciais.
POST Criar algo ou executar uma ação que processa dados. Renovar token no endpoint LWA mock.
PATCH Atualizar parcialmente um recurso existente. Atualizar preço e estoque de um SKU na Amazon mock.
PUT Substituir um recurso inteiro. Não é necessário neste desafio.
DELETE Remover um recurso. Não é necessário neste desafio.

Códigos HTTP

Código Categoria Interpretação prática
200 Sucesso A requisição funcionou e retornou dados.
202 Sucesso aceito A Amazon mock aceitou a atualização da oferta.
400 Erro do cliente A requisição está malformada ou inválida.
401 Não autorizado Token ausente, inválido ou expirado. Deve acionar renovação do token.
422 Dados inválidos O servidor entendeu a requisição, mas rejeitou o conteúdo.
429 Rate limit Muitas requisições. Deve haver retry com espera/backoff.
500 Erro do servidor Falha inesperada no servidor chamado.

Amazon SP-API E LWA

Amazon SP-API API de marketplace

SP-API significa Selling Partner API. É a API oficial da Amazon para vendedores, integradores e parceiros. Ela permite operar dados como pedidos, catálogo, preço, estoque, anúncios e relatórios.

No desafio, não usamos a SP-API real. Usamos uma API mock que simula o comportamento mínimo necessário para atualizar uma oferta existente.

LWA Login with Amazon

LWA é o mecanismo de autenticação da Amazon baseado em OAuth 2.0. Ele permite trocar um refresh_token por um access_token.

O access_token é enviado no header x-amz-access-token nas chamadas da Amazon. No mock, o token inicial sempre vem expirado para forçar o tratamento correto.

Access token credencial sensível

É o token temporário usado para autorizar chamadas à Amazon. Ele expira. Quando expira, a API pode retornar 401. A aplicação deve renovar e tentar novamente.

Refresh token credencial sensível

É o token usado para pedir novos access tokens. Ele é mais sensível que o access token porque permite gerar novos tokens. Nunca deve aparecer em logs.

Client ID e Client Secret credenciais

Identificam a aplicação junto ao provedor de autenticação. O client_secret funciona como uma senha da aplicação e também não deve ser logado.

Regra de segurança: logs podem mostrar SKU, status, motivo de falha e contadores, mas nunca devem mostrar access_token, refresh_token ou client_secret.

Termos De Negócio Da Integração

Plugar.me hub de integração

A Plugar.me atua como ponte entre sistemas como ERPs, e-commerces e marketplaces. Neste desafio, ela é a origem dos dados de produto, preço, estoque e credenciais Amazon.

Marketplace canal de venda

Marketplace é uma plataforma onde vários vendedores podem anunciar e vender produtos. Amazon Brasil é o marketplace de destino neste desafio.

ERP sistema de gestão

ERP é o sistema usado por empresas para controlar dados internos como produtos, estoque, preço, financeiro e pedidos. O campo erp_id representa o identificador do produto na origem.

SKU identificador comercial

SKU é o código usado para identificar um produto ou variação vendável. No desafio, o SKU enviado para a Amazon deve ser o valor de erp_id do produto Plugar.me.

Filial unidade operacional

Filial representa uma unidade da empresa. Um mesmo produto pode ter preços e estoques diferentes por filial. O desafio exige selecionar preço e estoque apenas da filial configurada em FILIAL_ID.

Oferta preço + disponibilidade

Neste contexto, oferta é o conjunto de informações comerciais do anúncio: preço, moeda, estoque disponível e canal de fulfillment. O anúncio já existe; a aplicação apenas atualiza a oferta.

Preço válido regra de negócio

Preço válido é um valor numérico que pode ser enviado para a Amazon. Produto sem preço da filial configurada deve ser ignorado e registrado em log.

Estoque zero valor válido

Quantidade 0 é válida. Ela significa que o produto está sem disponibilidade, mas ainda assim deve ser enviada quando houver preço válido e registro de estoque.

Arquitetura Recomendada

A forma mais clara de implementar é separar o código por responsabilidade. Isso mostra maturidade porque cada parte do sistema tem um motivo específico para existir.

Componente Responsabilidade
PlugarmeClient Buscar produtos e credenciais na API mock da Plugar.me.
AmazonAuthClient Renovar access token usando refresh token, client id e client secret.
AmazonListingsClient Enviar PATCH de preço e estoque para a Amazon Listings mock.
SyncAmazonOffersService Orquestrar o fluxo: buscar, filtrar, renovar token, publicar e consolidar resultado.
Controller ou Command Receber o disparo externo e chamar o serviço de sincronização.

Por que separar assim?

Porque a regra de negócio fica independente dos detalhes de HTTP. Se amanhã a URL mudar, o ajuste fica no client. Se a regra de filtro mudar, o ajuste fica no serviço. Isso facilita leitura, teste e manutenção.

Erros, Logs E Resiliência

Resiliência continuidade sob falha

Resiliência é a capacidade da aplicação continuar funcionando mesmo quando uma parte falha. No desafio, se um SKU falhar, os próximos SKUs ainda devem ser processados.

Retry nova tentativa

Retry é tentar novamente uma operação que falhou. Deve ser usado com cuidado. Para 429, um retry simples com espera progressiva é suficiente.

Backoff espera progressiva

Backoff é esperar um pouco antes de tentar de novo. Exemplo: primeira tentativa falha, espera 300 ms; se falhar de novo, espera 700 ms; depois marca como falha.

Observabilidade entender o que aconteceu

Observabilidade é a capacidade de investigar o comportamento da aplicação por meio de logs, métricas e resultados. No desafio, bons logs e uma resposta final bem organizada já ajudam bastante.

Boa prática: registre eventos como "SKU publicado", "SKU ignorado por ausência de preço" e "SKU falhou com status 422". Evite logs genéricos como "erro ao processar".

Glossário Completo

Mock simulação

Mock é uma simulação controlada de um sistema real. A API mock do desafio imita a Plugar.me e a Amazon para que a integração seja desenvolvida sem depender de serviços reais.

Endpoint ponto de acesso

Endpoint é uma URL específica de uma API. Exemplo: /plugarme/v1/produtos é o endpoint para buscar produtos.

Request ou Requisição pedido HTTP

É a mensagem enviada pelo cliente para o servidor. Inclui método, URL, headers, query params e, em alguns casos, body.

Response ou Resposta retorno HTTP

É a mensagem devolvida pelo servidor. Inclui status HTTP, headers e body.

Header metadado HTTP

Header é uma informação extra enviada em uma requisição ou resposta. Exemplo: Authorization: Bearer plugarme-test-token.

Authorization Bearer autorização

É um padrão comum para enviar token em APIs HTTP. "Bearer" indica que quem carrega aquele token tem permissão para acessar o recurso.

Query params parâmetros na URL

São valores enviados após o sinal ? na URL. Exemplo: ?cliente_id=1&filial_id=6.

Body corpo da requisição

É o conteúdo enviado na requisição. Em um PATCH, o body geralmente contém os dados que devem ser alterados.

Payload dados enviados

Payload é o conjunto de dados úteis enviados em uma requisição ou resposta. No desafio, o payload da Amazon contém productType e patches.

JSON formato de dados

JSON é um formato textual para representar objetos e listas. APIs modernas usam JSON porque é simples de ler, gerar e consumir.

Form URL Encoded formato de body

É um formato de envio de dados parecido com query params, mas no corpo da requisição. O endpoint de token usa application/x-www-form-urlencoded.

PATCH atualização parcial

PATCH é o método HTTP usado para atualizar parte de um recurso. No desafio, ele altera apenas preço e estoque de uma oferta existente.

Replace operação de patch

No payload da Amazon, replace indica que um atributo deve ser substituído. É usado para atualizar purchasable_offer, ou seja, o preço.

Merge operação de patch

merge combina os dados enviados com os dados existentes. No desafio, é usado para atualizar fulfillment_availability, ou seja, disponibilidade/estoque.

Product Type tipo de produto

Na Amazon, productType descreve o tipo de produto. O mock aceita PRODUCT para simplificar o teste.

Purchasable Offer preço da oferta

É o atributo da Amazon que representa a oferta comprável. No desafio, contém marketplace, moeda e preço com imposto.

Fulfillment Availability disponibilidade

É o atributo que representa estoque disponível para venda. No payload, inclui fulfillment_channel_code e quantity.

Marketplace ID identificador da praça

Identifica o marketplace específico dentro da Amazon. Para Amazon Brasil no mock: A2Q3Y263D00KWC.

Seller ID identificador do vendedor

Identifica a conta vendedora na Amazon. O PATCH de listing usa seller ID e SKU para encontrar o item certo.

Currency BRL moeda

BRL é o código ISO da moeda brasileira, o Real. O preço enviado à Amazon Brasil deve usar essa moeda no payload mock.

Idempotência repetição segura

Uma operação é idempotente quando repetir a mesma chamada tende a produzir o mesmo estado final. Atualizar o mesmo SKU com o mesmo preço e estoque deve deixar a oferta no mesmo estado.

Variáveis de ambiente configuração

São valores configurados fora do código, como URLs, tokens e IDs. Exemplo: PLUGARME_BASE_URL, CLIENTE_ID e FILIAL_ID.

.env arquivo local

Arquivo usado em desenvolvimento para definir variáveis de ambiente. Não deve conter segredos reais em repositórios públicos.

.env.example documentação de config

Modelo de arquivo com as variáveis necessárias, normalmente sem segredos reais. Serve para orientar quem vai rodar o projeto.

README guia do projeto

Documento principal com instruções de instalação, execução, testes, variáveis e decisões técnicas. É um dos entregáveis do desafio.

Client HTTP camada de integração

Classe ou módulo responsável por chamar uma API externa. Exemplo: PlugarmeClient chama a API da Plugar.me.

Service regra de negócio

Service é uma classe que concentra uma operação de negócio. No desafio, o serviço de sincronização decide o que publicar, ignorar ou marcar como falha.

Controller entrada HTTP

Controller recebe uma requisição HTTP no AdonisJS, chama a regra de negócio e devolve uma resposta.

Validator validação

Validator confere se dados de entrada estão no formato esperado. Pode ser útil caso a rota aceite parâmetros como cliente_id e filial_id.

Tipagem contratos no código

Tipagem descreve quais campos e formatos um valor possui. Em TypeScript, isso reduz erros e melhora leitura do código.

DTO objeto de transporte

DTO é um objeto usado para transportar dados entre camadas. Pode ajudar a separar o formato recebido da API do formato usado internamente.

Contrato formato combinado

Contrato é o acordo sobre entrada e saída de uma função, API ou componente. Exemplo: o contrato do PATCH da Amazon exige productType e patches.

Log registro de evento

Log é uma mensagem registrada pela aplicação para explicar o que aconteceu. Bons logs ajudam a entender erros e decisões, como produtos ignorados.

Segredo dado sensível

Segredo é qualquer dado que não deve ser exposto, como tokens, senhas e client secrets. Mesmo em teste, evitar logar segredos mostra cuidado profissional.
